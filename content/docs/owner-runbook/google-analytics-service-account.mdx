# Replace the Google Analytics Key with a Service Account

**Why:** the website admin's **Analytics** page reads numbers from Google Analytics using a
saved credential. The one saved today is a personal Google login, and Google's re-sign-in
policy has expired it, so every request fails. Since josemadridsalsa PR #551 the page says so:

> Google rejected the saved Google Analytics credential because it has expired or been revoked.

A **service account** is a robot Google account made for this. It doesn't expire when a
person's password or sign-in policy changes.

**Time:** about 15 minutes.

**You need:** the Google account that administers the Google Analytics property, access to
console.cloud.google.com, and an Admin login on the website.

<Steps>
<Step>
### Pick a Google Cloud project and switch on the API

1. Go to **console.cloud.google.com** and choose a project at the top. If the site already uses
   one for Google Maps or Calendar, use that one. Otherwise **New project**, name it
   `jose-madrid-website`.
2. **APIs & Services → Library**, search **Google Analytics Data API**, open it, click **Enable**.
</Step>

<Step>
### Create the service account

1. **IAM & Admin → Service Accounts → Create service account**.
2. Name: `ga-reporting`. Description: "Reads GA4 for the website admin". Click **Create and continue**.
3. Skip the optional role and user-access steps (click **Continue**, then **Done**). The account
   needs no Google Cloud permissions; its access is granted inside Google Analytics in step 4.
4. Copy the account's email address from the list. It looks like
   `ga-reporting@<project-id>.iam.gserviceaccount.com`. You'll need it in step 4.
</Step>

<Step>
### Download a key

1. Click the new service account → **Keys** tab → **Add key → Create new key** → **JSON** →
   **Create**.
2. A `.json` file downloads. **This file is a password.** Keep it on your computer only until
   step 5 is done.

<Callout type="warn" title="If key creation is disabled">
Google Workspace organizations often block key downloads with the policy
`iam.disableServiceAccountKeyCreation`. If you see that message, an Organization Policy
Administrator can allow it for this one project: **IAM & Admin → Organization Policies →
Disable service account key creation → Manage policy → Override parent's policy → Off** for this
project. Then try step 3 again.
</Callout>
</Step>

<Step>
### Give the service account read access in Google Analytics

1. **analytics.google.com → Admin** (gear, bottom left). Make sure the property at the top is the
   website's property.
2. Under **Property**, open **Property access management**.
3. Click **+ → Add users**, paste the service account email from step 2, untick **Notify new
   users by email**, choose the role **Viewer**, click **Add**.
4. While you're in Admin, open **Property details** and note the **Property ID** (a number like
   `123456789`, not the `G-...` measurement ID).
</Step>

<Step>
### Save the key in the website admin

1. Website admin → **Analytics** (`/admin/analytics`). Check the **GA4 Property ID** field matches
   the number from step 4. Fix and save it if not.
2. Website admin → **Settings → Integrations** (`/admin/settings/integrations`).
3. Scroll to **Add or rotate credentials** and fill in:
   - **Service name**: `google_analytics`
   - **Key name**: `service_account`
   - **Secret value**: open the downloaded `.json` file in a text editor, select everything,
     copy, and paste it here. It starts with `{` and contains `"type": "service_account"`.
   - Tick **Enable immediately**.
4. Click **Save integration**. The same service and key name replace the old credential; there's
   nothing to delete first.
</Step>

<Step>
### Check it

- [ ] `/admin/analytics` shows the summary cards (sessions, users and so on) with numbers.
      A brand-new range may show zeros, but no error message.
- [ ] On `/admin/settings/integrations`, the `google_analytics / service_account` row shows
      **Enabled**, and **Last used** updates after you load the analytics page.

Then **delete the downloaded `.json` file** from your computer and empty the trash. The
website has its own encrypted copy.
</Step>
</Steps>

## If it still fails

| Message on `/admin/analytics` | Cause | Fix |
|---|---|---|
| "Google rejected the saved Google Analytics credential…" | The pasted value isn't the new key, or the key was deleted in Google Cloud | Redo step 5 with the full file contents |
| "Failed to load Google Analytics data" | Usually a permission problem: the service account isn't a Viewer on **this** property, the Property ID is wrong, or the API isn't enabled | Recheck steps 1, 4 and 5.1. Permission changes can take a few minutes |
| "Add your GA4 property ID…" | Property ID field is empty | Step 5.1 |

## Later: rotating the key

Google recommends replacing service account keys about once a year. Repeat steps 3 and 5, check
the analytics page, then delete the old key under the service account's **Keys** tab.
