# Shipping Configuration

The shipping system in Jose Madrid Salsa uses a multi-tier strategy: real carrier API rates with fallback to estimate-based rates, ensuring checkout is never blocked.

<Callout type="warn" title="No free-shipping threshold">
Shipping is charged on every storefront order, regardless of subtotal — `calculateShipping()` has no free-shipping path. The only free shipping the business offers is on **fundraiser orders of 96 jars or more** and on **freight negotiated individually with distributor/wholesale accounts**; neither is handled by the calculator.
</Callout>

## How Shipping Calculation Works

The `calculateShipping` function in `lib/shipping-calculator.ts` follows this strategy:

<Steps>
<Step>
### Load Rate Config and Origin

The admin-configurable flat-rate presets are loaded first (this never throws — it falls back to built-in defaults). If the warehouse origin is incomplete, the calculator goes straight to estimate rates rather than quoting from a placeholder address:

```typescript
const rateConfig = await getShippingRateConfig()

const originResult = await getShippingOrigin()
if (!originResult.ok) {
  console.error(`[Shipping Calculator] ${describeMissingOrigin(originResult.missing)}`)
  return calculateEstimateRates(input, true, rateConfig)
}
```
</Step>

<Step>
### Call Carrier API

For domestic orders, the system calls the carrier API with the calculated parcel:

```typescript
const parcel = calculateOrderParcel(items)
const shipmentRequest: ShipmentRequest = {
  fromAddress: originResult.origin,
  toAddress: { ... },
  parcel,
}
const ratesResponse = await getShippingRates(shipmentRequest)
```
</Step>

<Step>
### Filter, Sort, and Add the Packaging Fee

Rates are filtered based on address type (PO Box addresses only get USPS options) and sorted by cost. Only the cheapest rate is offered, with the packaging fee added:

```typescript
if (isPoBox) {
  filteredRates = ratesResponse.rates.filter((rate) =>
    rate.carrier.toUpperCase().includes('USPS')
  )
}
const sortedRates = [...filteredRates].sort((a, b) => a.rate - b.rate)
const cheapestRate = sortedRates[0]
const cost = withHandlingFee(cheapestRate.rate)
```
</Step>

<Step>
### Fallback to Estimates

If the API fails or returns no rates, the system falls back to estimate-based rates (which also include the packaging fee) to never block checkout:

```typescript
} catch (error) {
  console.error('[Shipping Calculator] Error calculating shipping:', error)
  // ...
  return calculateEstimateRates(input, true, rateConfig)
}
```
</Step>
</Steps>

## Shipping Rate Configuration

The flat-rate presets for the estimate/fallback path live on the `ShippingSettings` singleton (in whole cents) and are editable at `/admin/settings/shipping` under **Flat-rate presets**. Any field left empty falls back to the built-in defaults in `lib/shipping/rate-config.ts`:

```typescript
export const DEFAULT_RATE_CONFIG: ShippingRateConfig = {
  flatRateCents: 699,
  weightSurchargeBaseCents: 499,
  weightSurchargePerLbCents: 50,
  weightSurchargeThresholdLb: 5,
  internationalRateCents: 2499,
  stateSurcharges: { AK: 1.5, HI: 1.5, PR: 2.0 },
}
```

### Packaging Fee

Every quote — live carrier rate, domestic estimate, or international flat rate — has a flat packaging-and-materials fee added once per order. It is a constant in `lib/shipping/handling-fee.ts`, not an admin setting:

```typescript
export const HANDLING_FEE_CENTS = 400
```

<Callout type="info">
There is no free-shipping threshold setting. The `freeShippingThreshold` column was dropped from `ShippingSettings` by migration `20260810100000_remove_free_shipping`.
</Callout>

## Origin Address Configuration

The origin is resolved by `lib/shipping/origin.ts`: the admin setting at `/admin/settings/shipping` first, then these environment variables:

```bash
SHIPPING_ORIGIN_ADDRESS="123 Main St"
SHIPPING_ORIGIN_CITY="San Francisco"
SHIPPING_ORIGIN_STATE="CA"
SHIPPING_ORIGIN_ZIP="94111"
SHIPPING_API_KEY="..."  # Carrier API key
```

## PO Box Detection

The system automatically detects PO Box addresses and restricts shipping options to USPS-only. `isPOBox()` upper-cases the address, strips periods, and tests:

```typescript
const poBoxPatterns = [
  /\bP\s*O\s+BOX\b/,           // PO BOX, P.O. BOX, P O BOX
  /\bPO\s+BOX\b/,              // PO BOX
  /\bPOST\s+OFFICE\s+BOX\b/,  // POST OFFICE BOX
  /\bP\s*O\s*B\b/,             // POB, P.O.B
  /^\s*BOX\s+\d+/,              // BOX 123 (only at start of address)
]
```

## Address Validation

Use the built-in validation before submitting shipping requests:

```typescript
import { validateShippingAddress } from '@/lib/shipping-calculator'

const result = validateShippingAddress({
  address1: '123 Main St',
  city: 'San Francisco',
  state: 'CA',
  postalCode: '94111',
  country: 'US',
})

if (!result.valid) {
  console.error(result.errors)
  // ["State must be a 2-letter code (e.g., CA, NY)"]
}
```

## Frontend Shipping Estimates

For real-time shipping previews, use the lightweight estimate function:

```typescript
import { getShippingEstimate } from '@/lib/shipping-calculator'

const estimate = await getShippingEstimate({
  subtotal: 35.00,
  state: 'CA',
  country: 'US',
})
// Returns: 10.99 ($6.99 flat rate x state multiplier + $4.00 packaging fee),
// whatever the subtotal
```

## Parcel Dimensions

The system calculates the parcel from order items via `calculateOrderParcel()`:

- **Jar-only orders**: Packed on the warehouse grid (`lib/shipping/jar-packing.ts`), which also computes gross weight (glass, lid, contents, dividers, box)
- **Other items**: Volume fit against standard box sizes; weight is the sum of item weights
- **Weight units**: `Product.weight` is in **ounces**

<Callout type="info" title="Weight Defaults">
If a product has no weight set in the database, the calculator assumes 16 oz per unit (`DEFAULT_ITEM_WEIGHT_OZ`). Set accurate weights and dimensions in the product editor for better rate accuracy.
</Callout>
